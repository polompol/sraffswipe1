# Безопасность StaffSwipe

Коротко о том, как устроена защита и что делать, если что-то утекло.
Документ для владельца и любого, кто будет трогать этот код.

## Нашли уязвимость — куда писать

Не открывайте публичный issue: он виден всем, включая того, кто может ей
воспользоваться. Напишите владельцу в Telegram (контакт — в приложении,
кнопка «Поддержка»). Ответ — в течение нескольких дней.

## Что защищает приложение

| Что | Как |
|---|---|
| Вход | Подпись Telegram initData (HMAC-SHA256) со сроком годности. Без валидной подписи вход невозможен: `ALLOW_INSECURE_TELEGRAM_AUTH` в проде запрещён проверкой при старте |
| Сессия | JWT HS256, секрет ≥32 символов — иначе сервер не поднимется. Срок 7 дней; приложение переполучает токен само и молча, поэтому короткий срок не мешает |
| Потеря телефона | «Завершить сессии» в админке обрывает доступ мгновенно. То же происходит при переносе аккаунта на новый Telegram и при удалении данных |
| Админка | Только Telegram-id из `ADMIN_TG_IDS`. Проверка идёт по базе на каждый запрос, а не по данным из токена |
| Код прихода | 6 цифр из `secrets`, сравнение постоянное по времени, не более 5 попыток в минуту |
| Вход по SMS | Не более 3 сообщений в минуту на номер, 5 попыток ввода кода |
| Вход через Telegram | Не более 30 попыток в минуту с одного адреса |
| Деньги | Списание только атомарным UPDATE с условием. Комиссия — одна запись на смену, повторное начисление невозможно |
| Оплата | Вебхук ЮKassa идемпотентен по id платежа, сумма сверяется с тем, что мы просили |
| Личные данные | Телефон, ИНН и точные координаты не отдаются в общую ленту. Фото документов не хранятся вообще |
| Заголовки | HSTS, CSP без внешних скриптов, nosniff, Permissions-Policy, открытие приложения разрешено только Telegram |
| Тело запроса | Не больше 2 МБ — отсекается прокси до чтения в память |
| Загрузка фото | Тип проверяется по первым байтам файла, а не по слову клиента; размер ≤8 МБ проверяет само хранилище |
| Сверка платежей | `/admin/payments/reconcile` находит платежи, по которым не дошёл вебхук, и дозачисляет их |
| Возврат денег | `/admin/wallet/{id}/refund` — списание атомарным UPDATE, в минус баланс не уходит, движение остаётся в журнале |

## Что проверяется автоматически

`.github/workflows/security.yml` на каждый push и раз в неделю:

- **gitleaks** — секреты во всей истории коммитов (удалить файл мало: коммит остаётся);
- **pip-audit** — известные уязвимости в зависимостях Python;
- **npm audit** — то же для того, что уезжает в браузер;
- **CodeQL** — статический анализ кода.

Еженедельный запуск важнее, чем кажется: уязвимость в библиотеке находят не
в тот день, когда мы правим код.

## Что делать, если утёк секрет

Секреты живут только в `.env` на сервере и в репозиторий не попадают. Если
всё-таки утекло — **менять, а не удалять коммит**: файл из истории убрать
можно, но считать его успели.

| Что утекло | Что делать |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/revoke` → новый токен в `.env` → перезапуск |
| `JWT_SECRET` | Новый через `bash scripts/gen-secrets.sh`. Все сессии разлогинятся — это нормально |
| `POSTGRES_PASSWORD` | Сменить в базе и в `.env`, перезапустить |
| `INTERNAL_API_SECRET` | Новый и перезапуск |
| Ключи ЮKassa / S3 | Отозвать в личном кабинете провайдера, выпустить новые |

После смены — проверить бэкапы: `bash scripts/backup.sh` и убедиться, что
дамп снимается.

## Что осознанно НЕ сделано на пилоте

Честный список, чтобы не создавать ложного ощущения защищённости:

- **Рейт-лимит живёт в памяти одного процесса.** Перезапуск сервера сбрасывает
  счётчики, а при нескольких воркерах лимит делится между ними. Пока
  `WEB_CONCURRENCY=1` это работает; при росте нагрузки — Redis.
- **Витрина активности намеренно обезличена.** Раньше она показывала «Имя
  вышел(ла) в «Заведение» — N ₽» любому вошедшему; теперь только роль и город.
  Смысл витрины — показать, что сервис живой, а не кто где работает.
- **Скрапинг ленты кандидатов ограничен, но не исключён.** Зарегистрироваться
  «заведением» может кто угодно, и лента отдаёт имя, год рождения, район и
  фото. Частота ограничена (30 обновлений в минуту), объём выборки — тоже,
  но упорный сборщик за часы наберёт заметный кусок базы. Настоящее решение —
  открывать ленту только заведениям, опубликовавшим хотя бы одну смену;
  это меняет продукт, поэтому решать после первых живых заведений.
- **Двухфакторной защиты у оператора нет** — доступ к админке даёт сам
  Telegram-аккаунт. Включите на нём облачный пароль (2FA) в настройках
  Telegram: это и есть второй фактор для админки.
- **Шифрования базы на диске нет.** Защита — доступ к серверу по ключу и
  закрытые порты.
- **Аудит-лога действий оператора нет.** Оператор один, но при появлении
  второго это станет нужно.
