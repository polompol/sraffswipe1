# StaffSwipe — визуальная проверка

Проверка в сентябре 2026. Проверяется изменение существующего Mini App по предоставленным изображениям и `StaffSwipe_UX_System_V2_50_Screens.html`; дополнительный проход — черновики, приглашения, оплата, адаптация и админка.

## Источник и область проверки

Исходный HTML просмотрен и разобран на 50 состояний. Для сверки его страницы отображались без изменения исходного CSS в iframe 390×844 рядом с работающим React-приложением такого же размера. Системная строка Telegram/телефона в исходнике нарисована; в приложении она не дублируется. Скриншоты ниже содержат обе версии в одном изображении.

## Пять поверхностей дизайна

| Проверка | Что проверено |
| --- | --- |
| Типографика | Антиква связывает бренд и крупные заголовки с ресторанной темой; интерфейсные условия и формы остаются системным шрифтом. Иерархия цены, профессии и названия читается на телефоне. |
| Отступы и размеры | Проверены 390×844 и компактная высота 568 px. Убрано перекрытие тела карточки действиями. Формы используют шаги и вертикальную прокрутку; чат резервирует высоту своего композера. |
| Цвета | Кремовый/бордовый сохраняют заданную палитру. Условия не лежат поверх фотографии. Проверки светлой/тёмной темы и крупных элементов прошли в E2E. |
| Изображения | Собственные WebP для старта/демо; галерея имеет ручное листание, счётчик и заглушку при ошибке. Нет автоматически пролистываемого фото во время принятия решения. |
| Содержание | Убран ложный смысл «деньги выплачены» у завершения; комиссия относится к заведению; код приходит от заведения; отзыв требует явной отправки. Непроверенные данные не превращаются в универсальные зелёные отметки. |

## Найдено и исправлено

| Находка | Исправление | Проверка |
| --- | --- | --- |
| Внешний `className` кнопки заменял базовые стили | Объединение классов после остальных props | Тесты кнопки и визуальный просмотр. |
| Жест колоды поглощал нажатие кнопки фото/деталей | Отключена избыточная фильтрация taps; защита от клика после drag сохранена | В браузере фото 1/2 → 2/2, подробности и возврат работают. |
| На низких экранах светлый блок условий перекрывался действиями | Уменьшена обязательная высота верхней области; второстепенные отметки скрываются по высоте | Финальный E2E: все девять размеров прошли; сохранён компактный снимок. |
| Одно нажатие звезды сразу отправляло отзыв | Выбор рейтинга → комментарий → «Отправить отзыв» | Тест компонента и браузерный выбор 5 звёзд без отправки. |
| Публикация была одной длинной формой | Три шага с валидацией и предварительным итогом | Обновлённые сквозные employer/full-path тесты прошли. |
| Закрытие описывалось как подтверждённая выплата | «По условиям смены», отдельное объяснение прямой оплаты | Просмотр завершённой карточки и сверка с backend. |
| Штамп поверх свайпа расходился с пожеланием «без печати» | Удалён штамп, оставлены движение и тактильный отклик | TypeScript, Vitest; обычные состояния колоды просмотрены. |
| Все профессии занимали большую часть первого шага | Один подписанный системный список вместо множества чипов | [До](docs/design-review/before-create-step1.jpg) / [после](docs/design-review/compare-create-step1.jpg), повторный E2E. |
| React 18 предупреждал о `fetchPriority` у стартового изображения | Использовано совместимое `loading="eager"` | Повторное открытие онбординга в новой вкладке и проверка консоли. |
| Боковые вырезы не учитывались при повороте | Общие safe-area токены слева/справа для страниц, вкладок, шторок, чата и уведомлений | Реальная браузерная геометрия на 320×568, 844×390 и 1024×768; тесты сначала воспроизвели проблему. |
| Выбор суммы сразу открывал платёж | Подтверждение назначения и суммы, явная отмена, повторное открытие той же ссылки и проверка баланса | Три unit-теста; шторка в браузере без создания реального платежа. |
| Сбой сети в админке выглядел как запрет доступа | Разделены 403, повтор запроса и offline-запуск; рабочие вкладки скрыты до ответа | Независимое ревью выявило paused-состояние React Query; три теста страницы после исправления. |
| Повтор квитанции публикации попадал под квоту новых смен | Квитанция возвращается до расходования квоты публикаций | Тест девяти обычных публикаций, десятого черновика, повторной квитанции и отказа следующей новой смене. |
| Неудачный employer match мог оставить отправленное приглашение | Интерес и создание договорённости фиксируются согласованно | Проверки полного штата, конкурентного отказа и сохранения прежнего отказа сотруднику. |

## Взаимодействие и ограничения среды

Пройдено: демо-регистрация сотрудника с именем/ролью/городом, лента, листание фото, открытие и закрытие подробностей, сохранение, переходы в смены/профиль/чат, фильтры текущих смен и истории, выбор оценки без отправки. Создание и предпросмотр смены, обе роли, чат/WS, код, расчёт, PDF и перекрывающие панели проверены существующими E2E с реальным тестовым API.

При сравнении смена страницы референса создаёт запись общей истории iframe: для возврата из чата пришлось сначала вернуться через запись референса. Это особенность временной страницы сравнения; она не поставляется с приложением.

В первой сессии попытка выйти из демо-профиля открыла браузерное `window.confirm`, после чего управляющий браузером CDP стал отвечать таймаутом. В дополнительном проходе 11 сентября выполнены регистрация заведения, просмотр кандидатов, три шага создания, возврат к условиям с сохранением ставки/оплаты/чаевых/описания, публикация тестовой смены и переход к её записи в списке. Реальный Telegram popup остаётся проверкой на устройстве.

При чтении полной доступной консоли дополнительного прохода найдено предупреждение React о `fetchPriority`, исправлено и перепроверено на стартовом экране. Остальные сообщения относились к расширению управляющего браузера (`chrome-extension://`), а не к приложению.

Итоговые автоматические результаты: backend 554 passed / 1 skipped; frontend 163 passed (30 файлов); E2E 51 passed (изолированный прогон, 4,1 минуты). Ruff, ESLint, TypeScript и production build прошли. Пропуск — реальный Redis Pub/Sub без установленного `redis-server`. Временные страницы сравнения удалены из `public`, чтобы не попадать в сборку.

Новые снимки настоящего интерфейса: [черновики](docs/design-review/drafts.jpg), [приглашения](docs/design-review/invitations.jpg), [подтверждение пополнения](docs/design-review/payment-confirm.jpg). В первых двух использованы тестовые записи настоящего API; в третьем подменён только ответ доступности платёжного сервиса, реального платежа нет. Снимок шторки сделан после завершения анимации, чтобы полупрозрачный промежуточный кадр не выдавался за дизайн.

Актуальные GitHub Actions привязаны к SHA в [PR #54](https://github.com/polompol/sraffswipe1/pull/54). При обновлении среды потребовалось восстановить браузер. Два E2E нельзя запускать одновременно: общий каталог trace и сборка приложения пересекаются. Итоговый прогон выполняется изолированно.
