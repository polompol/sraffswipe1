# Пуск сегодня: по кнопкам, от начала до работающего приложения

Для случая, когда **бот и домен уже есть, а сервера нет**. Всё делается с
телефона или с компьютера, займёт около полутора часов, из них 20–30 минут —
ожидание.

Что понадобится под рукой:

1. **Токен бота** от @BotFather (длинная строка вида `1234567890:AAE...`).
2. **Username бота** без собаки, например `staffswipe_bot`.
3. **Ваш Telegram-id** — напишите боту **@userinfobot**, он ответит числом.
   Без него не будет доступа в админку.
4. **Банковская карта** — сервер около 500 ₽/мес.
5. Если с телефона — приложение **Termius** (бесплатное, App Store / Google
   Play). Это окно, куда вводят команды на сервере.

---

## Шаг 1. Сервер (15 минут)

1. Откройте **timeweb.cloud** → «Регистрация», подтвердите почту.
2. «Облачные серверы» → **«Создать сервер»**.
3. **Образ ОС:** Ubuntu **24.04**.
4. **Конфигурация:** любая с **2 ГБ RAM** (обычно «2 × 2 ГБ × 30 ГБ», около
   500 ₽/мес). Меньше 2 ГБ не берите — не хватит на сборку.
5. **Регион:** Москва или Санкт-Петербург. Это требование закона: данные
   россиян должны храниться в России.
6. **Доступ:** «по паролю» — с телефона так проще.
7. Создать. Через 1–2 минуты в панели появится **IP-адрес** вида
   `81.200.15.42` и пароль root (он же придёт на почту).

**Запишите IP — он нужен на следующем шаге.**

---

## Шаг 2. Домен на сервер (5 минут + ожидание)

В панели того регистратора, где куплен домен (reg.ru, timeweb, nic.ru —
раздел называется «DNS» или «Управление зоной»):

Добавьте запись:

| Поле | Значение |
| --- | --- |
| Тип | **A** |
| Имя (субдомен) | `app` — если хотите `app.вашдомен.ру`. Для домена целиком поставьте `@` |
| Значение | **IP-адрес сервера** из шага 1 |
| TTL | оставьте как есть |

Сохраните. Дальше **10–30 минут ждём**, пока адрес разойдётся по интернету.
Это единственная пауза, которую нельзя ускорить. Проверить готовность:
откройте **dnschecker.org**, введите `app.вашдомен.ру` — должен появиться ваш
IP хотя бы в половине точек.

Пока ждёте — делайте шаг 3, он не зависит от домена.

---

## Шаг 3. Подключиться к серверу (5 минут)

**С телефона (Termius):** «+» → New Host → в поле Hostname впишите IP
сервера → Username: `root` → Password: пароль из панели → Connect. Появится
чёрный экран с текстом — это и есть сервер.

**С компьютера:** откройте терминал и введите `ssh root@ВАШ_IP`, затем
пароль. При вводе пароля символы не отображаются — это нормально.

При первом подключении спросят «Are you sure you want to continue
connecting?» — ответьте `yes`.

---

## Шаг 4. Подготовить сервер (10 минут)

Скопируйте **весь блок целиком** и вставьте в окно сервера, нажмите Enter.
Установка Docker займёт пару минут, будет много текста — это нормально.

```sh
apt update && apt install -y curl git
curl -fsSL https://get.docker.com | sh
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
```

Проверка, что Docker встал:

```sh
docker --version
```

Должна появиться строка вида `Docker version 27...`.

---

## Шаг 5. Скачать код (2 минуты)

```sh
git clone https://github.com/polompol/sraffswipe1.git
cd sraffswipe1
git checkout claude/staffswipe-flutter-app-6oqk55
```

Третья команда обязательна: вся свежая работа лежит в этой ветке, в `main`
её пока нет. Когда сольёте ветку в `main`, на сервере переключитесь обратно
(`git checkout main`).

Если репозиторий закрыт (приватный), `git clone` спросит логин и пароль —
вместо пароля нужен токен GitHub. Проще временно сделать репозиторий
публичным, склонировать и закрыть обратно.

---

## Шаг 6. Настройки (15 минут)

Сначала получите три случайных секрета — они понадобятся через минуту:

```sh
bash scripts/gen-secrets.sh
```

На экране появятся три строки вида `JWT_SECRET=8f3a...`. **Не закрывайте
это окно**, они сейчас пригодятся.

Создайте файл настроек и откройте его:

```sh
cp .env.example .env
nano .env
```

Открылся простой редактор. Стрелками двигайтесь по строкам и впишите свои
значения (всё, что после знака `=`, без кавычек и без пробелов):

| Строка | Что вписать |
| --- | --- |
| `DOMAIN=` | `app.вашдомен.ру` — **без** `https://` |
| `TELEGRAM_BOT_TOKEN=` | токен от @BotFather |
| `BOT_USERNAME=` | username бота без собаки |
| `POSTGRES_PASSWORD=` | скопируйте из вывода `gen-secrets.sh` |
| `JWT_SECRET=` | оттуда же |
| `INTERNAL_API_SECRET=` | оттуда же |
| `ADMIN_TG_IDS=` | ваш номер из @userinfobot |

Остальные строки оставьте как есть — они не обязательны на старте.

Сохранить и выйти из nano: **Ctrl+O**, затем **Enter**, затем **Ctrl+X**.
(В Termius эти сочетания есть на дополнительной клавиатуре над обычной.)

---

## Шаг 7. Запуск (10 минут)

```sh
docker compose -f docker-compose.prod.yml up -d --build
```

Первая сборка идёт 5–10 минут: скачиваются образы и собирается приложение.
Дальше запуск будет занимать секунды.

Проверьте, что всё поднялось:

```sh
docker compose -f docker-compose.prod.yml ps
```

Должно быть семь строк — `caddy`, `db`, `redis`, `api`, `scheduler`, `bot`,
`tma` — все в состоянии `Up`.

Проверьте, что сервер отвечает (подставьте свой домен):

```sh
curl https://app.вашдомен.ру/api/health
```

Ответ `{"status":"ok"}` означает, что **всё работает**: и сервер, и база, и
сертификат HTTPS (его Caddy получает сам, ничего настраивать не надо).

Если вместо ответа ошибка — смотрите шаг «Если что-то пошло не так» внизу.

---

## Шаг 8. Привязать к боту (5 минут)

Кнопку «Смены» и список команд **бот выставляет сам** при запуске. Просто
напишите своему боту `/start` — появится кнопка, нажмите её, приложение
откроется внутри Telegram.

Если кнопки нет, значит контейнер бота не поднялся: посмотрите
`docker compose -f docker-compose.prod.yml logs bot`.

Руками в @BotFather стоит оформить только карточку бота — то, что человек
видит до первого запуска: `/mybots` → ваш бот → **Edit Description** и
**Edit About**. Готовые тексты лежат в `docs/LAUNCH.md`, шаг 8. Картинка для
**Edit Botpic** — файл `tma/public/icon-512.png` из репозитория.

---

## Шаг 9. Проверка за пять минут

- [ ] `/start` боту → кнопка → приложение открылось.
- [ ] Прошли регистрацию как **соискатель**, лента открывается.
- [ ] В профиле внизу появилась строка **«Админ-панель»** — значит ваш
      Telegram-id вписан верно.
- [ ] Со второго аккаунта (или попросите знакомого) зашли как **заведение**
      и опубликовали смену.
- [ ] Соискателем свайпнули её вправо, заведение ответило — открылся чат.
- [ ] Написали боту любое слово — он ответил и предложил кнопку.

Прошло — **вы в проде**. Дальше можно звать первые заведения.

## Если что-то пошло не так

| Что видите | Что делать |
| --- | --- |
| `curl` не отвечает, сайт не открывается | Домен ещё не разошёлся или указывает не туда. Проверьте на dnschecker.org. Логи: `docker compose -f docker-compose.prod.yml logs caddy` |
| Ошибка 502 на `/api/health` | Не поднялся сервер приложения — почти всегда пустая строка в `.env`. Логи: `logs api` |
| Контейнер `api` перезапускается | В логах будет прямым текстом, какой переменной не хватает: сервер намеренно не стартует с пустыми секретами |
| Сборка падает с «no space left» | Мало места или памяти. Проверьте `df -h`, при 2 ГБ RAM должно хватать |
| Бот молчит | Неверный токен. Проверьте строку `TELEGRAM_BOT_TOKEN` в `.env`, потом `docker compose -f docker-compose.prod.yml up -d` |

**Присылайте мне текст ошибки целиком** — по нему сразу видно причину.

## Что делать потом

Обновить приложение, когда появятся изменения:

```sh
cd sraffswipe1 && git pull
docker compose -f docker-compose.prod.yml up -d --build
```

Ежедневные задачи (напоминания о сменах, предупреждения, закрытие зависших)
работают сами — их выполняет контейнер `scheduler`. Настраивать ничего не
нужно.

**Резервные копии базы** — единственное, что стоит настроить в ближайшие дни:
`docs/DEPLOY.md`, раздел 9. Без них потеря сервера означает потерю всех смен
и рейтингов.

**Реквизиты в оферте** (прочерки в `docs/legal/`) нужно заполнить до того,
как приведёте первых реальных людей.

**Когда подключите ЮKassa** — не забудьте настроить у неё HTTP-уведомление на
адрес приложения (`docs/LAUNCH.md`, раздел про ЮKassa, шаг 3). Без этого шага
деньги придут на счёт ЮKassa, а баланс заведения в приложении не пополнится:
человек заплатит и не увидит зачисления. Ежедневная сверка в 04:30 такие
платежи подберёт, но только на следующие сутки.
