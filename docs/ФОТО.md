# Фото: где лежат и как подключить (20 минут)

Фото в этом приложении — не украшение. Смену выбирают свайпом за секунду, и
карточка без фотографии просто пролистывается. Заведение без фото выглядит как
объявление на столбе, а анкета без фото — как анонимка.

Пока хранилище не подключено, фотографий не будет вообще: карточки показывают
первую букву названия, всё остальное работает как обычно. Вставить ссылку на
чужую картинку нельзя — сервер такие адреса отклоняет. Причина не в
придирчивости: владелец того сайта видел бы IP и устройство каждого, кто открыл
карточку, и мог бы подменить снимок уже после проверки.

---

## Где будут лежать фото

**В Yandex Object Storage — в России.** Это важно не из патриотизма: фотография
человека — персональные данные, и по 152-ФЗ данные россиян должны храниться на
серверах в России. Amazon, Cloudflare и подобные для этого не годятся, даже
если дешевле.

Подойдут любые российские S3-совместимые хранилища: **Yandex Object Storage**,
Selectel, VK Cloud, Timeweb Cloud. Инструкция ниже — про Яндекс, потому что у
него самая понятная панель и бесплатный старт. Для другого хранилища шаги те
же, поменяются только адрес и регион.

**Сколько это стоит.** Считайте сами: одно фото — примерно 300 КБ. Сто
заведений и триста анкет — это около 120 МБ, то есть **меньше 10 ₽ в месяц**.
Даже тысяча смен с фотографиями не выйдет за пределы сотни рублей. Платите
только за занятое место и за скачивания.

**Что именно там окажется:** фото заведений, фото мест (интерьер, зал, бар) и
фотографии из анкет соискателей. Файлы разложены по владельцам:
`photos/<id владельца>/<случайное имя>.jpg`. Документы — медкнижки, паспорта —
там не окажутся никогда: сервис их не хранит вовсе, только статусы.

## Шаг 1. Завести хранилище (10 минут)

1. Откройте **console.yandex.cloud** и войдите через свой Яндекс-аккаунт.
2. Создайте платёжный аккаунт, если его нет. Карту привязать придётся — но
   первые месяцы у вас будет уходить меньше десяти рублей.
3. Слева выберите **Object Storage** → **Создать бакет**.
   - **Имя** — латиницей, например `staffswipe-photos`. Имя видно в адресах
     картинок, менять его потом нельзя.
   - **Максимальный размер** — 1 ГБ (с запасом; можно увеличить в любой момент).
   - **Доступ на чтение объектов** — **публичный**. Это обязательно: браузер
     показывает фото по прямой ссылке, и без публичного чтения на месте
     фотографий будут пустые квадраты.
   - Доступ на запись и на список объектов — оставьте **ограниченным**.
4. Нажмите **Создать бакет**.
5. **Правило жизненного цикла — обязательно.** Откройте созданный бакет →
   **Жизненный цикл** → **Создать правило**:
   - **Префикс** — `photos/`
   - **Удалять объекты** — через **30 дней** после загрузки

### Зачем это правило

Бакет читается публично — иначе фото не покажутся. Это значит, что **любой
файл становится доступен по прямой ссылке сразу после загрузки**, ещё до того,
как он где-то появится в приложении.

Дальше простая арифметика. Ссылку на загрузку получает любой, кто вошёл в
сервис. Приложение перед выдачей ссылки проверяет первые байты файла, но
проверяет оно **пробу, которую прислал сам клиент**, а в хранилище файл потом
уезжает напрямую, минуя нас. То есть по честно выданной ссылке можно положить
что угодно — и получить постоянный адрес вида
`https://<ваш-бакет>.storage.yandexcloud.net/photos/…`, который выглядит как
адрес StaffSwipe.

Кодом это не закрывается: мы не видим байтов, которые уходят в хранилище, и
проверять их при сохранении анкеты бесполезно — файл уже лежит и уже доступен,
сохранять адрес злоумышленнику незачем.

Правило жизненного цикла превращает постоянный адрес во временный: что не
пересохранят, само исчезнет через месяц. Настоящие фотографии от этого не
страдают — приложение перезаливает их при каждой правке анкеты.

**Если вы пропустите этот шаг, сервис будет работать.** Но на вашем домене
появится бесплатное файловое хранилище, за трафик которого платите вы.

## Шаг 2. Разрешить браузеру загружать файлы (CORS)

Браузер отправляет фото **напрямую** в хранилище, минуя ваш сервер. Чужому
сайту хранилище по умолчанию отвечает отказом — надо разрешить именно ваш.

В бакете откройте вкладку **CORS** → **Добавить правило**:

| Поле | Значение |
| --- | --- |
| Разрешённые источники | `https://app.вашдомен.ру` (адрес приложения) |
| Разрешённые методы | `POST`, `GET` |
| Разрешённые заголовки | `*` |
| Максимальный возраст | `3600` |

Без этого правила загрузка молча не работает: человек выбирает фото, и ничего
не происходит.

## Шаг 3. Получить ключи

1. В консоли: **Identity and Access Management** → **Сервисные аккаунты** →
   **Создать сервисный аккаунт**. Имя — например `staffswipe-uploads`.
2. Роль — **storage.uploader** (и **storage.viewer**, если хотите смотреть
   файлы из консоли). Больше прав не давайте: этот ключ лежит на сервере, и чем
   меньше он умеет, тем спокойнее.
3. У созданного аккаунта: **Создать новый ключ** → **Статический ключ доступа**.
4. Появятся два значения — **идентификатор** и **секретный ключ**. Секретный
   показывается **один раз**: скопируйте сразу, потерянный не восстановить,
   придётся делать новый.

## Шаг 4. Вписать в настройки

На сервере откройте `nano .env` и заполните:

```
S3_ENDPOINT=https://storage.yandexcloud.net
S3_BUCKET=staffswipe-photos
S3_KEY=<идентификатор ключа>
S3_SECRET=<секретный ключ>
S3_PUBLIC_BASE=https://staffswipe-photos.storage.yandexcloud.net
S3_REGION=ru-central1
UPLOAD_ORIGIN=https://storage.yandexcloud.net
```

Две строки, о которых легко забыть:

- **`S3_PUBLIC_BASE`** — адрес, по которому фото показываются. Подставьте своё
  имя бакета вместо `staffswipe-photos`.
- **`UPLOAD_ORIGIN`** — без неё браузер заблокирует отправку файла ради вашей
  же безопасности, и снова «ничего не происходит».

Перезапустите:

```sh
cd ~/sraffswipe1
docker compose -f docker-compose.prod.yml up -d
```

## Шаг 5. Проверить

Внутри Telegram, в приложении:

- [ ] Профиль заведения → **Фото заведения** → выбрать картинку. Через пару
      секунд она появляется в кружке рядом с кнопкой.
- [ ] Опубликовать смену с **фото места** → открыть ленту работником: фото
      видно на карточке.
- [ ] Анкета соискателя → **Фото профиля** → сохранить → открыть ленту
      кандидатов заведением: фото на месте.

## Если не получилось

| Что видите | В чём почти наверняка дело |
| --- | --- |
| «Фото не загрузилось» на каждой попытке | Ключи не дошли до приложения. Проверьте, что строки в `.env` заполнены и вы перезапустили контейнеры |
| Ничего не происходит после выбора файла | Не заполнена `UPLOAD_ORIGIN` или не добавлено правило CORS (шаг 2) |
| В логах `SignatureDoesNotMatch` | Не тот `S3_REGION` (для Яндекса — `ru-central1`) или секретный ключ скопирован с пробелом |
| Фото загрузилось, но на его месте пустой квадрат | У бакета не включено **публичное чтение объектов** (шаг 1) или в `S3_PUBLIC_BASE` опечатка в имени бакета |
| «Это не похоже на картинку» | Файл не JPEG/PNG/WebP. Скриншоты с телефона подходят, документы и видео — нет |

Логи приложения: `docker compose -f docker-compose.prod.yml logs -f api`.

## Что сервис делает сам

Чтобы вы понимали, за чем не нужно следить:

- **Проверяет, что это картинка** — по первым байтам файла, а не по названию.
  Переименованный вирус с именем `photo.jpg` не пройдёт.
- **Ограничивает размер** — 8 МБ на файл, и это условие вшито в саму подпись:
  обойти его из браузера нельзя, иначе один человек забил бы хранилище (и ваш
  счёт) гигабайтами.
- **Не пропускает файл через ваш сервер** — браузер отправляет его прямо в
  хранилище. Сервер не тратит на это ни трафик, ни память.
- **Ограничивает частоту** — не больше 20 загрузок в минуту с аккаунта.
- **Раскладывает файлы по владельцам**, так что при удалении аккаунта видно,
  что именно удалять.
