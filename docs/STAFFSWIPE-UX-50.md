# StaffSwipe — дизайн и карта 50 экранов

Редакция: 11 сентября 2026. Основа — присланный `StaffSwipe_UX_System_V2_50_Screens.html`, два визуальных примера и действующая модель приложения.

Это карта целевого интерфейса с точным сопоставлением с кодом. Пятьдесят экранов примера — не пятьдесят независимых страниц: детали открываются внутри карточки, фильтры — в нижней панели, состояния смены — в списке и чате. Там, где функция примера ещё не реализована, это прямо указано.

## Визуальный язык

StaffSwipe — спокойная рабочая среда с атмосферой гостеприимства. Фотографии людей и заведений дают ощущение живого места; условия работы читаются на светлой поверхности. Главный акцент — бордовый. Печатей, штампов и романтических подписей у свайпа нет.

| Элемент | Решение |
| --- | --- |
| Основные цвета | Кремовый фон `#F7F2E9`, поверхность `#FFFDF8`, бордовый `#870E26`. Цветовые состояния используют существующие переменные темы. |
| Заголовки | Антиква для бренда и крупных заголовков. Системный шрифт для форм, условий, кнопок и переписки. |
| Иерархия карточки | Фото → профессия и название → оплата → дата/время → условия → подробности → решение. |
| Поля и отступы | Основное поле 16 px; интервалы 8/12/16/24/32 px. Скругления 14–20 px, мягкая тень только для разделения поверхностей. |
| Главное действие | Бордовая прямоугольная кнопка с ясным глаголом. «Откликнуться» для сотрудника, «Пригласить» для заведения. |
| Второстепенные действия | Светлая/контурная кнопка; пропуск — нейтральный крестик; сохранение — закладка. Сохранение не отправляет отклик. |
| Фото | До пяти фото сотрудника, счётчик и две кнопки перелистывания. Главное фото можно выбрать в профиле. У смены используются фото смены и заведения. |
| Движение | Небольшое движение при свайпе, переходах и нажатии; без автопрокрутки фотографий. Учитывается уменьшение анимации. |
| Маленький экран | В первую очередь остаются название, оплата, время и действие. Второстепенные отметки сокращаются; длинные формы прокручиваются. |
| Доступность | Подписи полей, названия и состояния кнопок, видимый фокус, область нажатия от 44 px. Есть тёмная тема и увеличение текста. |

Стартовые фото специально созданы для проекта; героиня вымышленная. Они используются в приветствии и демо, а в рабочих карточках отображаются реальные загруженные фотографии. Нельзя показывать демонстрационные рейтинги и отметки проверки в качестве данных настоящего заведения.

## Навигация

| Роль | Нижняя панель | Вложенные экраны |
| --- | --- | --- |
| Сотрудник | Лента · Мои смены · Профиль | Избранное, приглашения, редактирование, помощь и настройки. |
| Заведение | Лента · Люди · Смены · Профиль | Отклики, работники, создание/редактирование смены, комиссия, помощь. |
| Обе роли | Чат открывается из конкретной договорённости | В чате нет нижней навигации: место отдано сообщениям и вводу. Есть возврат и меню действий. |

Вложенный экран имеет явную кнопку назад и поддержку Telegram BackButton. Форма создания смены возвращает на предыдущий шаг с сохранением введённого. После публикации возврат ведёт к своим сменам. Открытие карточки не должно само отправлять отклик, приглашение или отзыв.

## Правила всех кнопок и форм

| Ситуация | Поведение |
| --- | --- |
| Нужен ввод | Поле имеет название; причина недоступности действия объяснена. В мастере ставка проверяется до публикации. |
| Запрос выполняется | Кнопка показывает загрузку; повторный вход/сохранение не должен создавать второй запрос. |
| Сервер отказал | Ошибка рядом с действием/уведомлением; карточка возвращается; заполненная форма остаётся. |
| Наложение панелей | Открытая нижняя панель перекрывает действия колоды и захватывает фокус; закрытие возвращает в контекст. |
| Несколько фото | Листание не открывает детали и не отправляет свайп. Недоступное фото заменяется аккуратной заглушкой. |
| Успех | Ясное подтверждение и следующий шаг; успех показывается после ответа сервера. |
| Выход из аккаунта | Явное подтверждение, очистка сессии и кэша личных данных. Запоздавший запрос старого аккаунта не подменяет новый. |
| Суммы и статусы | Источник — API. Предварительную сумму обозначаем знаком ≈; завершение и факт выплаты не смешиваем. |
| Проверка профиля | Показываем только тот вид проверки, который действительно выполнен. Заявленные документы и проверенная компания — разные признаки. |
| Админка | Только серверно подтверждённый владелец. До ответа сервера и при offline-запуске рабочие вкладки не монтируются. Отказ 403 и временный сбой имеют разные состояния. |

## Очерёдность оставшихся продуктовых доработок

Это отдельные функции, а не скрытые кнопки в готовой версии. Для каждой определён результат, который нужно принять перед включением.

| Приоритет | Функция | Что должно появиться |
| --- | --- | --- |
| После основных сценариев | Фоновое автосохранение | Сейчас сохранение явное — «Сохранить и выйти». Фоновая синхронизация потребует отдельной обработки конфликтов и незавершённой загрузки фото. |
| После основных сценариев | Адресное приглашение на смену | Базовый журнал уже работает. Для приглашения на конкретную смену и фильтра по ней нужна отдельная модель приглашения; сейчас точная смена появляется при взаимном отклике. |
| Следующий этап | Центр обращений | Номер, дата, связанная смена, статус и переписка; сотрудник видит только свои обращения; оператор работает через админку. |
| После согласования правил | Двухсторонний табель | План и факт, предложение изменения, кто подтвердил, версия условий, отказ/спор. Согласовать его связь с уже существующим автоматическим закрытием, затем менять API и расчёт. |
| После согласования проверки | Документы и галерея заведения | Разделить «указано», «отправлено», «проверено», «нужно исправить». Определить, кто и что проверяет, до показа зелёных отметок. |
| После основных сценариев | Сравнение кандидатов и блокировки | Сравнение 2–3 людей по одинаковым реальным полям; личная блокировка с отменой, влияющая на выдачу и контакты. |
