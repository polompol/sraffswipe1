# StaffSwipe — полная инструкция запуска (по шагам, с сайтами)

Это подробный путь от «ничего нет» до «приложение живое в Telegram».
Время: ~1–2 часа активных действий. Деньги: ~500–1000 ₽ (сервер + домен).

У тебя уже есть: **токен бота** и **домен**. Если чего-то нет — шаги 1–2
объясняют, где взять.

---

## Шаг 0. Что понадобится под рукой

- Телефон с Telegram (твой аккаунт).
- Банковская карта (оплатить сервер/домен).
- Ноутбук/ПК удобнее, но можно и с iPhone: поставь приложение
  **Termius** (App Store, бесплатно) — это SSH-клиент, через него
  вводят команды на сервере.

---

## Шаг 1. Бот в Telegram (если ещё не создан)

1. Открой Telegram → поиск → **@BotFather** (галочка верификации).
2. Отправь команду: `/newbot`
3. Он спросит имя — введи: `StaffSwipe`
4. Он спросит username — введи что-то свободное, оканчивается на `bot`,
   например: `staffswipe_bot`
5. BotFather пришлёт **токен** вида `1234567890:AAE...xyz` —
   **скопируй и сохрани**, никому не показывай.

## Шаг 2. Сервер (VPS)

Подойдёт любой из этих сайтов (все российские, платёж картой РФ):

- **timeweb.cloud** ← рекомендую, просто и дёшево
- selectel.ru
- beget.com

По шагам на Timeweb:
1. Зайди на **timeweb.cloud** → «Регистрация» (почта + пароль).
2. В панели: **«Облачные серверы» → «Создать сервер»**.
3. Образ ОС: **Ubuntu 24.04**.
4. Конфигурация: **2 CPU / 2 ГБ RAM / 30 ГБ диск** (~400–600 ₽/мес).
5. Регион: Москва (или Санкт-Петербург).
6. Создай сервер → через 1–2 минуты в панели появятся:
   **IP-адрес** (вида `185.xx.xx.xx`), логин **root** и **пароль**.
   Сохрани все три.

## Шаг 3. Домен → на сервер

Домен у тебя есть. Зайди в панель регистратора (где покупал домен —
reg.ru / timeweb / nic.ru), найди раздел **«DNS» / «Управление зоной»**:

1. Создай запись типа **A**:
   - Имя (хост): `app` (получится `app.твойдомен.ру`)
   - Значение: **IP сервера** из шага 2
   - TTL: оставь по умолчанию
2. Сохрани. Подожди 5–15 минут.
3. Проверка: на телефоне/ПК открой терминал (или сайт **dnschecker.org**,
   введи `app.твойдомен.ру`) — должен показать IP твоего сервера.

## Шаг 4. Юридические документы (152-ФЗ) — до публичного запуска

**Отдельно публиковать документы не нужно.** Тексты лежат в `docs/legal/`
(оферта, политика ПДн, правила), и при сборке приложения из них собираются
страницы, которые открываются прямо рядом с мини-аппом:

- `.../legal/offer.html` — оферта,
- `.../legal/privacy.html` — политика обработки персональных данных,
- `.../legal/terms.html` — правила сервиса.

Ссылки на них стоят на экране выбора роли (галочка «принимаю») и в
**Настройках → Документы**. Переменные `VITE_OFFER_URL` / `VITE_PRIVACY_URL`
из шага 6 нужны, только если ты захочешь держать документы на своём сайте.

⚠️ **Что обязательно сделать своими руками до публичного запуска:**

1. Заполнить прочерки `___` в трёх файлах `docs/legal/`: кто оператор (ИП /
   ООО / самозанятый), ИНН, адрес, e-mail для обращений, дата редакции.
   Пока там прочерки — документы неполные.
2. Вычитать и показать юристу. Тексты писались под то, что приложение
   реально делает, но это не юридическая консультация.
3. Проверить, что сервер физически в России — в политике написано, что данные
   хранятся в РФ (ст. 18 ч. 5 152-ФЗ). Если возьмёшь зарубежный хостинг, это
   будет неправдой и именно за это штрафуют.

Для закрытого теста со знакомыми можно начинать и с прочерками; для
публичного запуска — нет.

## Шаг 5. Подключиться к серверу и поставить Docker

С ПК (Windows: PowerShell; macOS: Терминал) или с iPhone через Termius:

```sh
ssh root@185.xx.xx.xx        # вместо xx — IP из шага 2, пароль пришлёт хостинг
```

Дальше по одной команде (копируй построчно):

```sh
curl -fsSL https://get.docker.com | sh
```
(ставится 1–2 минуты)

```sh
ufw allow 80 && ufw allow 443 && ufw allow 22
```
(открыть веб-порты; если ответит «command not found» — пропусти, фаервол выключен)

## Шаг 6. Скачать код и заполнить настройки

```sh
git clone https://github.com/polompol/sraffswipe1.git
cd sraffswipe1
```

Всё нужное лежит в основной ветке (`main`), переключаться никуда не надо.
Проверьте, что в `docker-compose.prod.yml` есть службы `redis` и
`scheduler`: **без планировщика смены не закрываются сами и комиссия не
начисляется вообще** — сервис будет работать, а денег не принесёт, и никто
об этом не сообщит.

Сгенерировать секреты (выведет четыре готовые строки, у каждой слева
написано её имя):

```sh
bash scripts/gen-secrets.sh
```

Создать файл настроек и открыть редактор:

```sh
cp .env.example .env
nano .env
```

В редакторе заполни (стрелками ходишь, печатаешь как обычно):

| Строка | Что вписать |
|---|---|
| `DOMAIN=` | `app.твойдомен.ру` (без https://) |
| `TELEGRAM_BOT_TOKEN=` | токен из шага 1 |
| `BOT_USERNAME=` | username бота без @ (напр. `staffswipe_bot`) |
| `POSTGRES_PASSWORD=` | значение из строки `POSTGRES_PASSWORD=` в выводе gen-secrets.sh |
| `JWT_SECRET=` | значение из строки `JWT_SECRET=` |
| `INTERNAL_API_SECRET=` | значение из строки `INTERNAL_API_SECRET=` |
| `ADMIN_TG_IDS=` | твой Telegram-id (узнать у бота **@userinfobot**) |
| `VITE_SUPPORT_URL=` | ссылка на твой чат поддержки, напр. `https://t.me/имя_чата`. Пусто — кнопка «Написать в поддержку» ведёт в чужой несуществующий чат |
| `VITE_OFFER_URL=` | оставь пустым — оферта открывается из самого приложения |
| `VITE_PRIVACY_URL=` | оставь пустым — политика открывается из приложения |

**Свой Telegram-id** узнай у бота **@userinfobot** и впиши в `ADMIN_TG_IDS` —
только тебе будет доступна админ-панель. Раньше id был вписан прямо в
шаблон, но репозиторий публичный, а это личные данные: держим его в `.env`,
который в репозиторий не попадает. Второй оператор — через запятую.

Сохранить и выйти из nano: **Ctrl+O → Enter → Ctrl+X**.

## Шаг 7. Запуск (одна команда)

```sh
docker compose -f docker-compose.prod.yml up -d --build
```

Первый запуск — 3–5 минут (собираются образы, берётся HTTPS-сертификат).

Проверка, что всё поднялось:

```sh
docker compose -f docker-compose.prod.yml ps
```
— у всех сервисов статус Up / Healthy.

```sh
curl https://app.твойдомен.ру/api/health
```
— должен ответить `{"status":"ok"}`.

Если что-то не так — смотри логи:
```sh
docker compose -f docker-compose.prod.yml logs -f api
docker compose -f docker-compose.prod.yml logs -f caddy
```

## Шаг 8. Карточка бота в BotFather

Кнопку «Смены» слева от поля ввода и список команд **бот выставляет сам**
при запуске — руками их настраивать не нужно. Проверка: напиши своему боту
`/start` → появится кнопка → нажми → **приложение откроется внутри
Telegram**. 🎉

Если кнопки нет — значит контейнер бота не поднялся (`logs -f bot`); можно
поставить её вручную: **@BotFather → /mybots → бот → Bot Settings → Menu
Button → Configure menu button**, URL `https://app.твойдомен.ру`, текст
`Смены`.

Руками остаётся оформить карточку — то, что человек видит до первого
запуска. В @BotFather → `/mybots` → твой бот:

**`Edit Description`** (крупный текст на пустом экране бота):

> Смены в кафе и ресторанах рядом с домом — на один день.
> Открой приложение, листай смены поблизости, откликайся в один тап.
> Оплата в день смены, напрямую от заведения.

**`Edit About`** (короткая строка в профиле бота, до 120 символов):

> Подработка в общепите рядом с домом. Смены на один день, оплата в день смены.

**`Edit Botpic`** — квадратная картинка. Готовая лежит в репозитории:
`tma/public/icon-512.png`.

**`Edit Commands`** трогать не нужно — бот прописывает их сам.

Отдельно: `/setdomain` для Mini App **не требуется** — он нужен только для
входа через Telegram Login Widget, которого у нас нет.

## Шаг 9. Смоук-тест (5 минут)

- [ ] Онбординг открывается, регистрация как **соискатель** проходит.
- [ ] Профиль открывается; внизу видна кнопка **«Админ-панель»**
      (значит `ADMIN_TG_IDS` вписан верно).
- [ ] Попроси знакомого (или второй аккаунт TG) зайти как **заведение**
      и создать тестовую смену.
- [ ] Соискателем свайпни её вправо → мэтч → чат работает.
- [ ] Обе стороны подтвердили смену → в чате появилось системное сообщение
      «Смена подтверждена ✓ Дальше ничего нажимать не нужно…». В день смены
      работают кнопки «Я на смене» (по коду от заведения) и «Человек пришёл»
      — но они не обязательны, смена закроется и без них.
- [ ] Админка → «Сегодня» → блок «Каждый день» → **«Напомнить о сменах на
      сегодня»**. Работнику приходит сообщение от бота, и кнопка в нём
      открывает **экран смен**, а не ленту вакансий.
- [ ] Там же остальные три кнопки нажимаются без ошибки: «Предупредить о
      завтрашних сменах без людей», «Закрыть вчерашние смены и начислить
      комиссию», «Спросить про вчерашние смены». На пустой базе они честно
      отвечают «закрывать пока нечего» — это нормально.
- [ ] Напиши боту любое сообщение (например «привет») — он должен ответить
      и предложить кнопку запуска, а не промолчать.
- [ ] Открой `https://app.твойдомен.ру` в обычном браузере телефона (не в
      Telegram) → меню → «Добавить на главный экран». На экране появится
      фирменная иконка, и приложение откроется без адресной строки. Внутри
      будет экран «StaffSwipe работает в Telegram» с кнопкой — **так и
      задумано**: входа без Telegram нет вовсе, там нет ни пароля, ни номера
      телефона. Значок на экране — просто короткий путь в приложение.

Всё прошло — **ты в проде**.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Сертификат не выдаётся / сайт не открывается | A-запись не указывает на сервер или порты 80/443 закрыты. Проверь dnschecker.org и `ufw status`. Логи: `logs -f caddy` |
| `/api/health` отвечает 502 | API не поднялся — чаще всего не заполнены секреты в `.env`. Логи: `logs -f api` |
| Кнопка в боте не открывает приложение | В BotFather URL должен быть ровно `https://app.твойдомен.ру` — с https, без слэша в конце |
| Нет кнопки «Админ-панель» | В `ADMIN_TG_IDS` не тот id — сверься с @userinfobot, перезапусти: `docker compose -f docker-compose.prod.yml up -d` |
| Поменял `.env` | Изменения применяются после `docker compose -f docker-compose.prod.yml up -d --build` |

## Приём комиссии картой (ЮKassa) — доступно САМОЗАНЯТОМУ, без ИП

Хорошая новость: ЮKassa подключается **самозанятому (НПД) без ИП**.

1. На **yookassa.ru** → «для самозанятых»: подключение онлайн, ~1 день.
   Нужны паспорт + ИНН, расчётный счёт НЕ требуется, абонплаты нет —
   только комиссия за проведённые платежи.
2. Получи `SHOP_ID` и `SECRET_KEY`, впиши в `.env`: `YOOKASSA_SHOP_ID`,
   `YOOKASSA_SECRET_KEY`, отдельный `YOOKASSA_WEBHOOK_SECRET` (это
   четвёртая строка из `scripts/gen-secrets.sh`), перезапусти. Кнопки «Пополнить картой»
   в приложении включатся сами.
3. **Обязательно: настрой уведомление в кабинете ЮKassa.** Без этого шага
   деньги придут на счёт ЮKassa, а баланс заведения в приложении НЕ
   пополнится — человек заплатит и не увидит зачисления.

   Личный кабинет ЮKassa → **Интеграция → HTTP-уведомления**:

   - адрес: `https://app.твойдомен.ру/api/billing/yookassa/webhook?secret=ТВОЙ_YOOKASSA_WEBHOOK_SECRET`
   - событие: **`payment.succeeded`** (остальные не нужны, они игнорируются)

   Секрет в адресе — это и есть защита: ЮKassa не подписывает свои запросы,
   поэтому чужой не сможет прислать поддельное «оплачено», не зная секрета.
   Адрес попадает в логи веб-сервера, но секрет из них вырезается (см.
   Caddyfile).

   Проверка: сделай пополнение на 1 ₽ и убедись, что баланс изменился в
   приложении. Если нет — админка → «Деньги» → «Сверить платежи с ЮKassa»
   дозачислит вручную, а значит уведомление настроено неверно.
4. **Чек по НПД не через ЮKassa**, а в приложении «Мой налог» —
   поэтому `YOOKASSA_SEND_RECEIPT=false` (значение по умолчанию, не меняй).
   `YOOKASSA_VAT_CODE=1` (без НДС) — тоже для самозанятого.

Ограничения самозанятого: доход ≤2,4 млн ₽/год, с карт до 500 000 ₽/мес,
платить могут только физлица (администратор кафе — со своей личной карты).
Для пилота с запасом.

**До подключения ЮKassa** пополнение баланса идёт вручную: заведение
переводит тебе по СБП → ты в админке жмёшь «Баланс +N ₽». Тоже работает.

## Подсказки адреса (DaData) — влияют на ленту «смены рядом»

Стоит знать заранее: **координаты смены берутся только из подсказки адреса**.
Заведение начинает вводить адрес, выбирает строку из выпадающего списка — и
вместе с адресом сохраняются координаты. Подсказки даёт DaData.

Без ключа DaData подсказок нет, значит у смены нет координат, значит в ленте
не будет расстояния до смены («1.6 км») и не сработает сортировка «Ближе» —
лента станет просто списком по городу. На отметку о выходе это не влияет: она
делается кодом, который заведение называет на месте.

Подключение: **dadata.ru** → регистрация → «API подсказок» (бесплатный тариф —
10 000 запросов в сутки, для пилота с запасом). В личном кабинете взять
**API-ключ** и **секретный ключ**, вписать в `.env` и перезапустить:

```sh
DADATA_TOKEN=<API-ключ>
DADATA_SECRET=<секретный ключ>
```

Тот же ключ используется для проверки заведения по ИНН (бейдж «Проверено»).

## Другие города

Сервис работает в любом городе России с первого дня — ничего дописывать не
нужно. Что важно знать:

- **Город выбирается из списка**, а не пишется руками. Это не про
  аккуратность: со свободным вводом «Санкт-Петербург», «СПб» и «Питер»
  становятся тремя разными городами, и люди из одного города перестают видеть
  друг друга — молча, без единой ошибки. Список городов лежит в
  `backend/app/cities.py`, добавить город — одна строка.
- **Время смены считается по часовому поясу её города.** Смена «10:00–18:00»
  во Владивостоке заканчивается на семь часов раньше московской, и от этого
  зависит, когда она закроется и когда начислится комиссия. Города из
  справочника это учитывают; город не из справочника работает по `BUSINESS_TZ`.
- **Заведение видит кандидатов своего города**, работник — смены своего.

## Перед всплеском трафика

Реклама, репост, ролик — за полчаса до этого стоит сделать две вещи:

1. `WEB_CONCURRENCY=2` (или 4 на сервере с 4 ГБ) и перезапуск. Процессы умеют
   работать вместе: общее состояние идёт через Redis.
2. Убедиться, что сервер не на минимальном тарифе: 2 ГБ памяти хватает, но
   впритык.

Вход выдерживает всплеск: ограничение — 300 попыток в минуту с одного адреса.
Это важно именно для мобильного трафика — операторы прячут тысячи абонентов за
одним адресом, и при прежнем лимите живые люди упирались бы в отказ.

## Хранилище фото (S3)

**Подробная инструкция с кнопками — [ФОТО.md](ФОТО.md).** Здесь коротко.

Фото — не украшение: смену выбирают свайпом за секунду, и карточка без
фотографии пролистывается. Без хранилища приложение честно предлагает вставить
ссылку на картинку вручную, всё остальное работает.

**Хранилище должно быть в России.** Фотография человека — персональные данные,
и по 152-ФЗ данные россиян хранятся на серверах в РФ; это же написано в вашей
политике обработки данных. Cloudflare R2, Amazon S3 и подобные не подходят,
даже если бесплатны. Годятся Yandex Object Storage, Selectel, VK Cloud,
Timeweb Cloud — код общий, меняются только адрес и регион.

Рекомендую **Yandex Object Storage**: понятная панель, счёт в рублях, а на
пилоте это меньше 10 ₽ в месяц (одно фото ≈ 300 КБ).

```sh
S3_ENDPOINT=https://storage.yandexcloud.net
S3_BUCKET=staffswipe-photos
S3_KEY=<идентификатор статического ключа>
S3_SECRET=<секретный ключ>
S3_PUBLIC_BASE=https://staffswipe-photos.storage.yandexcloud.net
S3_REGION=ru-central1
UPLOAD_ORIGIN=https://storage.yandexcloud.net
```

Три вещи, которые легко пропустить, — и каждая выглядит одинаково («фото не
грузятся, ошибок нет»):

1. **`UPLOAD_ORIGIN`.** Файл уходит в хранилище напрямую из браузера, минуя ваш
   домен. Без этой строки браузер зарежет отправку МОЛЧА.
2. **Правило CORS в бакете** — разрешить `POST` с адреса приложения. Иначе
   отказывает уже само хранилище.
3. **Публичное чтение объектов** у бакета. Без него фото загрузится, но на его
   месте будет пустой квадрат.

После правки достаточно `docker compose -f docker-compose.prod.yml up -d` —
пересборка не нужна, эти настройки читаются при запуске.

## Посмотреть приложение в Telegram уже сегодня (без сервера)

Приложение умеет работать на **демо-данных** — без бэкенда и без сервера.
Этого хватает, чтобы открыть его на своём телефоне прямо в Telegram и
показывать заведениям «вот как это выглядит». Займёт минут 15.

**Шаг 1. Бот** (см. подробно шаг 1 выше): @BotFather → `/newbot` → имя →
username, оканчивающийся на `bot`. Сохрани токен.

**Шаг 2. Выложить приложение на Vercel**

1. **vercel.com** → войти через GitHub → **Add New… → Project**.
2. Импортировать `polompol/sraffswipe1`.
3. **Deploy** — больше ничего настраивать не нужно. В корне репозитория лежит
   `vercel.json`, который уже говорит Vercel, что собирать (приложение из
   папки `tma`). Через 2 минуты получишь адрес вида `staffswipe.vercel.app`.

Переменные окружения задавать не нужно: без `VITE_USE_BACKEND=true`
приложение само работает на демо-данных.

**Шаг 3. Привязать к боту**

@BotFather → `/mybots` → твой бот → **Bot Settings → Menu Button →
Configure menu button** → пришли адрес с Vercel → текст кнопки `Открыть`.

Напиши боту `/start`, нажми кнопку — приложение откроется внутри Telegram.

### Что важно понимать про этот режим

Это **витрина, а не рабочий сервис**. На демо-данных:

- ничего не сохраняется — закрыл приложение, всё вернулось к началу;
- два разных человека не увидят друг друга, мэтча между реальными людьми не будет;
- деньги, комиссия и акты не работают.

Поэтому показывать заведениям — можно и нужно, а вот **регистрировать их
как реальных клиентов нельзя**: они ничего не получат. Для настоящего
пилота нужен сервер (шаги 2–8 выше), после чего в BotFather просто меняешь
адрес кнопки на свой домен.

## Лендинг на Vercel

**Уже выложен и открывается публично: https://staffswipe.vercel.app**

Пока это текстовая версия — без двух скриншотов приложения (их не получилось
залить через API). Чтобы появились картинки и страница начала обновляться
сама при каждом `git push`, подключи репозиторий — это 3 клика:

1. **vercel.com** → войти через GitHub → **Add New… → Project**.
2. Импортировать репозиторий `polompol/sraffswipe1`.
3. В настройках проекта указать **Root Directory: `landing`** и
   Framework Preset: **Other** (сборка не нужна) → **Deploy**.
   Здесь Root Directory указать НУЖНО: по умолчанию корневой `vercel.json`
   собирает приложение, а не лендинг.

Через минуту получишь адрес вида `staffswipe.vercel.app`. Свой домен
привязывается там же (Settings → Domains).

Само приложение (`tma/`) на Vercel вешать не нужно: оно должно жить на том
же домене, что и API, иначе придётся отдельно настраивать CORS и адрес
бэкенда. Его раздаёт Caddy из `docker-compose.prod.yml`.

## Ошибки в проде (Sentry) — опционально, но советую

Чтобы падения приходили тебе, а не оставались незамеченными:

1. На **sentry.io** → создай проект типа **FastAPI** → скопируй **DSN**.
2. Впиши `SENTRY_DSN=<твой DSN>` в `.env` и перезапусти.

Пакет уже в зависимостях — больше ничего делать не нужно. Если DSN пустой,
приложение работает как обычно, просто без отправки ошибок.
